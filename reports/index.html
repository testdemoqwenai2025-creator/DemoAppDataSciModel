BI Reports

Saved BI reports

Reports saved from the Analytics Studio. Each captures the analytic type, columns, and source dataset at the time of saving — so you can build a recurring report library for stakeholders. Reports persist in your browser; in a full engagement they would live in a server-side store with scheduling and distribution.

How reports work

Save a report from any Analytics Studio view (on Live Demo, Notebooks, or any data-upload page) by clicking the Save as report button below the analytic. The report captures the analytic type, primary and secondary column selections, source dataset, and row count.

This page lists saved reports for review. In a full engagement this evolves into scheduled execution (cron + server-side render), distribution lists (email / Slack / SharePoint), versioned snapshots (weekly PDFs of the same report), and embedded dashboards (iframe-able URLs). For now it demonstrates the workflow: analyse → save → revisit.

Graduate to 24/7 server-side cron
The browser scheduler above only fires while this page is open. For true 24/7 scheduled renders, deploy this GitHub Actions workflow to your private repo. It runs on GitHub-hosted runners, renders on schedule, and archives snapshots as workflow artifacts (90-day retention).
.github/workflows/scheduled-report-render.yml
# .github/workflows/scheduled-report-render.yml
# True 24/7 scheduled report rendering for DSModelPro BI reports.
#
# This workflow runs on GitHub-hosted runners (free for public repos,
# billed per-minute for private repos). It renders reports on a cron
# schedule and stores snapshots as workflow artifacts (90-day retention).
#
# To extend: replace the "Render report" step with a call to your
# warehouse query layer, push the rendered output to S3/GCS, and email
# distribution lists.

name: Scheduled report render

on:
  schedule:
    # Every Monday at 09:00 UTC — adjust to match your schedule
    - cron: '0 9 * * 1'
  workflow_dispatch:  # Allow manual runs from the Actions tab

permissions:
  contents: read
  actions: write  # Required to upload artifacts

jobs:
  render:
    name: Render scheduled reports
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - name: Checkout report definitions
        uses: actions/checkout@v4

      - name: Setup Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.13'

      - name: Install dependencies
        run: |
          pip install playwright pandas
          playwright install --with-deps chromium

      - name: Render report
        env:
          WAREHOUSE_URL: ${{ secrets.WAREHOUSE_URL }}
          REPORT_ID: weekly-summary
        run: |
          # In a real engagement this script:
          #   1. Loads the report definition (analytic type, columns)
          #   2. Queries the warehouse for fresh data
          #   3. Renders to PDF/PNG using Playwright headless browser
          #   4. Saves the snapshot with timestamp
          python scripts/render_report.py --report-id "$REPORT_ID" \
            --output "snapshot-$(date -u +%Y%m%dT%H%M%S).pdf"

      - name: Upload snapshot artifact
        uses: actions/upload-artifact@v4
        with:
          name: report-snapshot-${{ github.run_id }}
          path: snapshot-*.pdf
          retention-days: 90

      - name: Summary
        run: |
          echo "## Scheduled render complete" >> $GITHUB_STEP_SUMMARY
          echo "" >> $GITHUB_STEP_SUMMARY
          echo "**Report:** $REPORT_ID" >> $GITHUB_STEP_SUMMARY
          echo "**Trigger:** ${{ github.event_name }}" >> $GITHUB_STEP_SUMMARY
          echo "**Run ID:** ${{ github.run_id }}" >> $GITHUB_STEP_SUMMARY
          echo "" >> $GITHUB_STEP_SUMMARY
          echo "Snapshot archived for 90 days. Extend this workflow to push" >> $GITHUB_STEP_SUMMARY
          echo "to S3/GCS or email distribution lists." >> $GITHUB_STEP_SUMMARY
