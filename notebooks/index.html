Phase 4

Jupyter notebooks — in-browser Python

JupyterLite is Jupyter compiled to WebAssembly — it runs Python in the browser with no server. Query the dimensional model, compute statistics, and prototype analytical logic, all client-side. This is Phase 4 of the evolution: turning DSModelPro into a self-contained analytical workbench.

Why JupyterLite?

Traditional Jupyter needs a Python server. JupyterLite runs entirely in the browser via WebAssembly — no server, no install, no backend. It is perfect for a reference platform like DSModelPro because it lets users experiment with the dimensional model without provisioning infrastructure.

Combined with the DataUploadPanel (lazy streaming parse) and the ExportPanel (download CSV/JSON/SQL), this turns DSModelPro into a complete analytical loop: upload data → parse → analyse in Python → export results. All client-side.

How the preview works (lazy evaluation)

Clicking Preview in browser generates a 100-row synthetic dataset that matches the real dataset's column structure and inferred types. The Analytics Studio then runs on this preview — summary statistics, distribution histograms, correlation heatmaps, scatter plots and more — all client-side, no download. For the real multi-GB/TB datasets, a server-side proxy (the data-source-service) would stream the actual data through the same lazy parser used by the DataUploadPanel.

How this connects to the rest of DSModelPro

The analytical loop is: Upload (DataUploadPanel, lazy streaming) → Parse (online statistics) → Export (CSV/JSON/SQL) → Analyse (JupyterLite, this page) → Re-export (from the notebook).

In a future phase, the notebook could read directly from the warehouse (via a Pyodide SQLite plugin or a server-side query API), making the loop real-time rather than export-based.
